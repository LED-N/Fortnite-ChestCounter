# 復号鍵チェック修正と日本語対応

## 目的

ゼロ埋め鍵のリプレイを復号してパディング例外になる問題を修正し、日本語で設定・集計結果を利用できるようにする。

## 方針

- 暗号化リプレイの鍵が空または全ゼロなら復号へ進めない。ライブラリ側でも検査し、直接利用時も原因の分かる例外にする。
- 書き込み中・終了直後のファイルは既存の安定待ちと再試行の対象にし、十分な時間が経った鍵なしファイルは解析不能として扱う。完了フラグだけで鍵を有効と判断しない。
- ファイルが更新された場合は既存のファイル識別規則に従い再解析できるようにする。
- 過去にパディング例外として記録されたファイルも、更新後の再評価対象にする。
- 正常な暗号化リプレイおよび非暗号化リプレイの解析を維持する。
- 鍵の生成元の修正、鍵の復元は対象外。既存の対象2本が解析可能になることは保証しない。

## 日本語対応

- 既存の `L` 翻訳処理に `ja` を追加する。初回の言語選択、設定保存、`--lang ja`、日本語Windowsの初期選択を対応させる。
- コンソール、設定、エラーメッセージ、オーバーレイ、HTMLレポート、宝箱・アイテム表示名、日付、順位、個数表記を日本語対応する。
- 保存済みのフランス語の内部名称やデータ形式は維持し、表示時に翻訳する。ユーザーが編集した名称やゲーム内識別子は勝手に翻訳しない。
- 既存のフランス語・英語・スペイン語の動作を維持する。READMEに日本語での起動方法を追記する。

## 検討した方法

- 採用提案: 既存の翻訳処理を拡張する。現状の言語切替に自然に組み込め、保存データとの互換性を維持できる。
- 別案: 翻訳処理全体を外部リソース方式へ置き換える。今回の日本語追加に対して変更範囲が広いため採用しない。
- エラー修正は鍵の検証を採用する。パディングの変更や例外の無条件な無視は、復号できないデータを正常扱いするため採用しない。

## 検証・成果物

- 空鍵、ゼロ埋め鍵、有効な鍵、非暗号化、録画状態の違い、既存エラーの再評価を回帰検証する。
- 日本語の言語選択・設定・数値表示・名称と既存言語への切替を検証する。
- ReleaseビルドとWindows用EXEの発行を行い、日本語のHTML・オーバーレイ表示を確認する。
- 調査資料・引き継ぎ資料を更新する。現在のフォルダーは `.git` がないため、現状のままではコミットできない。
